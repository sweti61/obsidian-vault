# 🎯 INDEX / NOINDEX / MERGE

Methodisches Entscheidungsschema für die SEO-Klassifikation
einzelner Seiten.

Diese Notiz ist eine **Referenz**, kein Plan. Sie hilft, neue
Seiten zu klassifizieren und bestehende Klassifikationen zu
überprüfen.

---

# 🧠 Grundprinzip

Eine Seite kann drei Funktionen haben:

| Funktion | Bedeutung | Wirkung |
|---|---|---|
| **INDEX** | Seite ist für Google sichtbar | Traffic + Ranking |
| **NOINDEX** | Seite ist nur für Menschen erreichbar | Vertrauen + Conversion |
| **MERGE** | Seite wird in eine andere integriert | Autoritäts-Konzentration |

Die Frage ist nicht "ist die Seite gut?", sondern **"welche Funktion soll sie haben?"**.

Eine schlechte Seite kann durch INDEX schaden. Eine gute Seite kann durch NOINDEX
ihre eigentliche Wirkung entfalten. Eine wertvolle Seite kann durch MERGE
zur Stärkung einer Hauptseite beitragen.

---

# 🟢 INDEX – wann

Eine Seite gehört in den **Index**, wenn **alle vier Kriterien** erfüllt sind:

## Kriterien

1. **Konkrete Suchintention von Klienten**
   Klienten googeln tatsächlich danach. Beispiele: "Mediator Dresden",
   "Erbschaftsstreit Geschwister", "Pflegekonflikt Familie",
   "was kostet Mediation", "Streit Nachbarschaft Lärm".

2. **Eigenständige Positionierung**
   Die Seite ist nicht eine von vielen ähnlichen, sondern hat ein klar
   abgegrenztes Thema oder einen klar abgegrenzten Anlass.

3. **Kein thematischer Doppelgänger**
   Es gibt keine zweite Seite auf der Domain, die für dieselbe
   Suchintention ranken könnte.

4. **Klientenorientierte Sprache**
   Die Seite ist für die Zielperson geschrieben (Privatperson 50+,
   pflegender Angehöriger, Erbe), nicht für Fachpublikum
   (Mediator, Jurist, Sozialwissenschaftler).

## Funktion

→ **Traffic + Ranking generieren**
→ Klienten zur Seite führen, die nach Hilfe suchen
→ Conversion-Pfad öffnen (CTA: Erstgespräch)

## Beispiele aus mediator.sweti.de

- `/mediator-dresden/` (regional)
- `/pflegende-angehoerige-dresden/` (Zielgruppe + Lokal)
- `/themen/erbstreit-familie-klaeren-dresden/` (Pillar)
- `/post/streit-nachbarn-laerm-was-tun/` (konkrete Klientenfrage)
- `/post/was-kostet-mediation-dresden/` (FAQ-Suche)

# 🔴 NOINDEX – wann

Eine Seite gehört auf **noindex**, wenn **mindestens eines** der folgenden
Kriterien zutrifft:

## Kriterien

### Kriterium A – Abstrakte Begriffe ohne Suchintention

Slugs wie "Ruhe", "Vertrauen", "Klarheit", "Beziehung beruhigen",
"Rolle klären" beschreiben Zustände, nicht Suchanlässe.

### Kriterium B – Fachpublikum als Zielgruppe

Theorie-Artikel, Methoden-Erklärungen, Modell-Beschreibungen
für Mediator-Kollegen, Studierende, Fach-Interessierte.

Beispiele für Fachpublikum-Indikatoren:
- Slug enthält Theorie-Begriffe ("Harvard-Konzept", "9-Felder-Modell",
  "BATNA", "Hypothesenbildung")
- Slug enthält Phasen-Bezeichnungen ("Klärungsphase P2", "P4
  Umsetzungsphase")
- Slug enthält reine Begriffsnomen ohne Anliegen ("Reframing",
  "Ressourcenorientierung", "Eigenverantwortung")

### Kriterium C – Starke Überschneidung mit anderer Seite

Es existiert eine andere Seite auf der Domain, die thematisch
ähnlich ist und besser positioniert ist. Die zweite Seite würde
nur Konkurrenz erzeugen.

### Kriterium D – Mehrdeutige Semantik

Begriffe, die in unterschiedlichen Kontexten unterschiedlich
verstanden werden (privat vs. Organisation, methodisch vs. anlassbezogen).

### Kriterium E – B2B-Inhalt auf Privatkunden-Marke

Thema gehört zu einer anderen Domain (z.B. B2B-Themen auf
mediator.sweti.de, die eigentlich zu beltschew.de gehören).

## Funktion

→ **Vertrauen + Conversion**
→ Seite bleibt für Direktaufrufe, LinkedIn-Verlinkung, interne Verlinkung
   und persönliche Empfehlungen erreichbar
→ Stärkt das Profil der Domain ohne Google-Konkurrenz mit eigenen
   Hauptseiten

## Beispiele aus mediator.sweti.de

**Kriterium A – Abstrakte Begriffe:**
- `/angebote/beziehung-beruhigen/` (Zustand, kein Suchanlass)
- `/angebote/ruhe-schaffen/` (Zustand)
- `/angebote/vertrauen-aufbauen/` (Zustand)

**Kriterium B – Fachpublikum:**
- `/post/9-felder-modell-kochernz/`
- `/post/harvard-batna/`
- `/post/klaerungsphase-p2-systemische-mediation/`
- `/post/eigenverantwortung/` (Mediations-Grundprinzip)

**Kriterium C – Überschneidung:**
- `/angebote/zusammenarbeit-klaeren/` (Doppelung mit beltschew.de-Themen)

**Kriterium D – Mehrdeutigkeit:**
- `/angebote/rolle-klaeren/` (privat oder Organisation?)

**Kriterium E – B2B auf Privatkunden-Marke:**
- `/post/konflikte-itsm/` (B2B-Thema)
- `/post/itil_mediation/` (B2B-Thema)
- `/zielgruppen/it/` (B2B-Zielgruppe)

# 🟡 MERGE – wann

Eine Seite ist Kandidat für **MERGE**, wenn:

## Kriterien

1. **Inhaltliche Substanz vorhanden**
   Die Seite enthält wertvollen Inhalt, der nicht verloren gehen sollte.

2. **Thematisch nahes Ziel existiert**
   Es gibt eine Hauptseite (Landingpage, Pillarseite, Angebotsseite),
   in deren Kontext der Inhalt gehört.

3. **Inhalt würde Hauptseite stärken**
   Durch den Merge wird die Hauptseite substantieller, nicht überladener.

4. **Klienten-übersetzbar**
   Der Fachinhalt lässt sich in 200–400 Wörter Klienten-relevanter
   Sprache übertragen, ohne den Klienten-Fokus der Hauptseite zu
   verwässern.

## Funktion

→ **Autoritäts-Konzentration**
→ Verstreute thematische Substanz wird zu einem starken Hauptpunkt
→ Google sieht eine starke Antwort statt mehrerer schwacher
→ Quelle wird per 301 zur Zielseite umgeleitet, Linkkraft fließt mit

## Verfahren – Reihenfolge entscheidend

Niemals umgekehrt – sonst geht der Inhalt verloren, bevor er auf der
Zielseite ankommt.

```
1. Klienten-relevanten Kern aus Quelle extrahieren (200-400 Wörter)
2. Klar Klientensprache formulieren (kein Fachjargon)
3. In Zielseite einfügen (Accordion am Ende, vor CTA)
4. Bauen, deployen, prüfen
5. Erst danach: 301-Redirect in .htaccess setzen
6. Quelle aus Hugo-Source löschen (oder im /_archiv/ behalten)
```

## Wichtig: NOINDEX als Zwischenstufe

**MERGE ist eine Q3-Aufgabe, nicht sofort.** Die Reihenfolge ist:

1. **Sofort:** Seite auf `noindex` setzen (entzieht sie dem
   SEO-Wettbewerb)
2. **Q3 oder später:** Inhalts-Merge umsetzen + 301-Redirect
3. **Nach Verarbeitung des Redirects (4-6 Wochen):** Quelle löschen

Dadurch wird der Inhalt geschützt, der SEO-Schaden begrenzt, und
die redaktionelle Arbeit kann in Ruhe geplant werden.

## Beispiele aus mediator.sweti.de

| Quelle | Ziel | Begründung |
|---|---|---|
| /post/dienstleistung-elder/ | /pflegende-angehoerige-dresden/ | Inhalt hilft der Landingpage |
| /post/elder-mediation/ | /pflegende-angehoerige-dresden/ | Substanz für Hauptzielgruppe |
| /post/systemische-auftragsklaerung/ | /angebote/konfliktklaerung-vorbereiten/ | Methodischer Kern für die Landingpage |
| /post/klaerungsphase-p2-systemische-mediation/ | /themen/mediation-verstehen/ | Vertiefungs-Akkordion auf Pillarseite |

# 🚫 Wann nicht MERGE, sondern nur NOINDEX

Nicht jede noindex-Seite ist Merge-Kandidatin. Wenn **eines** zutrifft,
nur noindex setzen, kein Merge planen:

- **Keine thematische Nähe** zu einer Landingpage
  (z.B. `/post/harvard-konzept/` – kein direktes Pendant)
- **Inhalt wäre auf der Landingpage störend**
  (z.B. tiefes Theorie-Material würde den Klienten verwirren)
- **Inhalt wertet Landingpage ab**
  (z.B. wenn die Theorie unsicher klingt oder die Methodik zu
  technisch ist)
- **Quelle ist substantielle eigene Ressource für Fachpublikum**
  (z.B. Cluster-Artikel zu den Mediations-Grundprinzipien als
  Zukunfts-Konsolidierung)

# 🔄 Cluster-Konsolidierung als Sonderform von MERGE

Wenn mehrere noindex-Artikel zum gleichen Thema existieren, kann statt
"MERGE in Landingpage" auch "MERGE zu einem Hauptartikel" sinnvoll sein.

## Beispiele

**Cluster Harvard-Konzept (7 Artikel):**
- /post/harvard-batna/
- /post/harvard-emotionen-beduerfnisse/
- /post/harvard-konzept/
- /post/harvard-kriterien/
- /post/harvard-mp/
- /post/harvard-optionen/
- /post/harvard-po-vs-in/

→ Q3-Idee: zu einem zusammenfassenden Artikel
"Das Harvard-Konzept im Mediationskontext" konsolidieren.

**Cluster Mediations-Grundprinzipien (7 Artikel):**
- /post/eigenverantwortung/
- /post/empathie/
- /post/ergebnisoffenheit/
- /post/freiwilligkeit/
- /post/informirtheit/
- /post/neutralitaet_unabhaengigkeit/
- /post/Vertraulichkeit/

→ Q3-Idee: zu einem zusammenfassenden Artikel
"Die Prinzipien der Mediation" konsolidieren.

## Verfahren

1. Inhalte aller Cluster-Artikel zusammenführen
2. Strukturieren (Einleitung, Hauptteil mit Unterabschnitten,
   praktische Bedeutung, Fazit)
3. Einen neuen, starken Artikel erstellen
4. Alle Quell-Artikel per 301 auf den neuen umleiten

# 🧭 Entscheidungsbaum

Vor jeder Klassifikation diese Fragen in dieser Reihenfolge stellen:

```
1. Ist es B2B-Inhalt auf der Privatkunden-Domain?
   JA → noindex, später Migration zu beltschew.de
   NEIN → weiter mit 2

2. Ist es ein Theorie- oder Methodik-Artikel für Fachpublikum?
   JA → weiter mit 3
   NEIN → weiter mit 5

3. Gibt es eine thematisch nahe Landingpage, die der Inhalt
   stärken könnte?
   JA → MERGE-Kandidat (noindex jetzt, Merge in Q3)
   NEIN → weiter mit 4

4. Gibt es ein Cluster ähnlicher Theorie-Artikel?
   JA → noindex jetzt, Cluster-Konsolidierung in Q3
   NEIN → noindex jetzt, kein Merge geplant

5. Hat die Seite eine konkrete Suchintention von Klienten?
   JA → weiter mit 6
   NEIN → noindex (abstrakte Begriffe, Funktion: Conversion)

6. Gibt es einen thematischen Doppelgänger auf der Domain?
   JA → der schwächere bekommt noindex oder MERGE
   NEIN → INDEX

7. Ist die Seite klientenorientiert geschrieben?
   JA → INDEX
   NEIN → überarbeiten (Klientensprache) ODER noindex
```

# 📊 Anwendung – Übersicht der Klassen für mediator.sweti.de

| Klasse | Bedeutung | Aktion sofort | Aktion später |
|---|---|---|---|
| **INDEX** | Klientensuche, eigenständig | bleibt | bei Bedarf inhaltlich schärfen |
| **NOINDEX – Fachpublikum** | Theorie für Kollegen | `noindex: true` | Cluster-Konsolidierung Q3 |
| **NOINDEX – abstrakt** | Wirkungs-Seiten ohne Suchintention | `noindex: true` | bleibt für Conversion |
| **NOINDEX – Doppelgänger** | Konkurriert mit Hauptseite | `noindex: true` + 301 | – |
| **NOINDEX – B2B-Verschiebung** | Falsche Marken-Zuordnung | `noindex: true` | Migration zu beltschew.de |
| **MERGE-vorbereiten** | Substanz für Hauptseite | `noindex: true` | Inhalts-Merge + 301 in Q3 |

# 🛠️ Technische Umsetzung in Hugo (Ananke-Theme)

## NOINDEX setzen

Im FrontMatter der `.md`-Datei oder `_index.md`:

```yaml
---
title: "..."
date: ...
noindex: true
---
```

Verifikation nach Deploy:
- Browser → URL → Strg+U → Strg+F → `noindex`
- Erwartet: `<meta name="robots" content="noindex">`

## INDEX (Standard)

Kein FrontMatter-Eintrag nötig. Wenn `noindex: true` gesetzt war,
einfach diese Zeile entfernen oder auf `false` setzen.

## MERGE / 301-Redirect

In `.htaccess` (STRATO-Hosting, Apache):

```apache
RewriteRule ^post/quell-slug/?$ /angebote/ziel-slug/ [R=301,L]
```

Test nach Deploy:

```bash
curl -I https://mediator.sweti.de/post/quell-slug/
# Erwartet: HTTP/2 301
# Location: /angebote/ziel-slug/
```

Oder mit https://httpstatus.io/

# 🚥 Stop-Bedingungen

**Wenn nach 4 Wochen seit Klassifikations-Anwendung folgendes auftritt:**

- Indexierte Seiten sinken **deutlich** unter den Ausgangsstand
- Klicks insgesamt sinken statt zu steigen
- Marken-Suchanfragen ("Sweti", "Beltschew", "Mediator Sweti")
  bringen weniger Traffic

**Reaktion:** Pause. Datenanalyse. Möglicherweise einzelne Klassifikationen
zurücknehmen. Niemals stur weitermachen.

# 📝 Klassifikations-Tagebuch

Bei jeder Klassifikation einer neuen Seite oder Re-Klassifikation einer
bestehenden Seite Folgendes dokumentieren:

```markdown
## YYYY-MM-DD – Klassifikation [URL]

- **Klasse:** INDEX / NOINDEX-Fach / NOINDEX-abstrakt / MERGE
- **Begründung:** ...
- **Ziel (falls MERGE):** ...
- **Aktion:** noindex gesetzt / Redirect gesetzt / unverändert
- **GSC-Status vor Aktion:** indexiert / nicht-indexiert / unbekannt
- **Beobachtung nach 7 Tagen:** ...
```

Funktion: Über Wochen und Monate sichtbar machen, welche Klassifikations-
Entscheidungen welche Wirkung hatten. Lernende Praxis.

# 🔄 Wiedervorlage und Re-Klassifikation

Klassifikation ist **nicht statisch**. Folgende Anlässe können eine
Re-Klassifikation auslösen:

- **GSC zeigt Suchanfragen, die du nicht erwartet hattest**
  → Eventuell Klasse INDEX statt NOINDEX, weil tatsächliche
    Suchintention vorhanden ist
- **Du fügst eine neue Landingpage hinzu**
  → Bestehende NOINDEX-Artikel werden Merge-Kandidaten
- **Cluster wächst**
  → Cluster-Konsolidierung könnte sinnvoll werden
- **B2B-Domain (beltschew.de) ist aufnahmebereit**
  → B2B-NOINDEX-Artikel werden zu Migrations-Kandidaten

Empfohlener Rhythmus: **Halbjährliche Klassifikations-Review**, in der
alle bestehenden NOINDEX-Seiten kurz geprüft werden, ob die Klassifikation
noch passt.
